## 2. 🛡️ Lecciones Críticas de Base de Datos (Prevención de Errores)

### A. Secuencias de Claves Primarias (`_pkey`) vs. Inserciones Manuales
- **Problema detectado**: Las tablas creadas con `id bigint generated by default as identity primary key` (como `public.productos`) no avanzan automáticamente su secuencia interna (`*_id_seq`) cuando se insertan registros con IDs manuales o mediante restauraciones/scripts de migración.
- **Consecuencia**: Al intentar insertar un nuevo registro omitiendo `id`, PostgreSQL genera el valor de la secuencia desfasada que ya existe, disparando el error:
  ```text
  code: 23505, duplicate key value violates unique constraint "productos_pkey" (Key (id)=(X) already exists)
  ```
- **Regla Mandatoria**:
  1. Si se detecta este error o se importan datos con IDs fijos, ejecutar en Supabase SQL Editor:
     ```sql
     SELECT setval(pg_get_serial_sequence('public.productos', 'id'), COALESCE((SELECT MAX(id) FROM public.productos), 1));
     ```
  2. Sincronización preventiva para todas las tablas:
     ```sql
     DO $$
     DECLARE
       r RECORD;
       v_max_id BIGINT;
       v_seq_name TEXT;
     BEGIN
       FOR r IN (
         SELECT table_schema, table_name, column_name
         FROM information_schema.columns
         WHERE table_schema = 'public'
           AND (column_default LIKE 'nextval(%' OR is_identity = 'YES')
       ) LOOP
         v_seq_name := pg_get_serial_sequence(r.table_schema || '.' || r.table_name, r.column_name);
         IF v_seq_name IS NOT NULL THEN
           EXECUTE format('SELECT COALESCE(MAX(%I), 0) FROM %I.%I', r.column_name, r.table_schema, r.table_name) INTO v_max_id;
           IF v_max_id > 0 THEN
             PERFORM setval(v_seq_name, v_max_id);
           END IF;
         END IF;
       END LOOP;
     END;
     $$;
     ```
  3. **Auto-recuperación en código**: En acciones de servidor (`+page.server.ts`), capturar errores con `productos_pkey` o `Key (id)=`, consultar `MAX(id)`, sumar 1 y reintentar inmediatamente con `id: nextId` de forma transparente.

### B. Consecutivos de Códigos de Negocio (`codigo_key`)
- Para correlativos como `tipos_producto.consecutivo_actual` (`CAJ-000001`, `SOB-000001`):
  - La función `public.generar_codigo_producto` debe usar `FOR UPDATE` y un bucle `WHILE EXISTS` para no colisionar con códigos preexistentes.
  - En la aplicación, ante código `23505` sobre `codigo_key`, recalcular `MAX` del prefijo, actualizar `tipos_producto` y reintentar.

### D. Prevención de Bloqueos en Despliegue
- **Problema detectado**: `npm install` o ejecuciones locales en el VPS modificaban `package-lock.json`, lo que bloqueaba la ejecución de `git pull origin "$CURRENT_BRANCH"`.
- **Regla Mandatoria**:
  El script `deploy.sh` en el VPS y los comandos de despliegue siempre deben descartar cambios sucios con:
  ```bash
  git checkout -- package-lock.json deploy.sh 2>/dev/null || true
  git fetch origin "$CURRENT_BRANCH"
  git reset --hard "origin/$CURRENT_BRANCH"
  ```

## 4. 💻 Guía para Continuar en Otro Equipo con Antigravity

Al abrir este proyecto en una nueva computadora o máquina de desarrollo:

### Paso 1: Clonar y configurar credenciales SSH
Asegúrate de tener acceso SSH a GitHub y a los VPS:
```bash
git clone git@github.com:josecarmona/logistic.git
cd logistic
```
*(Copiar la clave SSH `id_rsa` autorizada a `~/.ssh/id_rsa` para acceso a los VPS `199.231.184.201` y `69.163.184.102`).*

### Paso 2: Configurar archivo `.env`
Crear el archivo `.env` en la raíz del proyecto para desarrollo local:
```env
PUBLIC_SUPABASE_URL=https://vgwyblazkfdsrrlbwhof.supabase.co
PUBLIC_SUPABASE_ANON_KEY=<value>
SUPABASE_SERVICE_ROLE_KEY=<value>

SESSION_REFRESH_INTERVAL=3600
GEOCODING_API_URL=https://nominatim.openstreetmap.org
GEOCODING_USER_AGENT=logistic-app
```

### Paso 3: Instalar dependencias y verificar
```bash
npm install
npm run check
npm run build
```

### Paso 4: Iniciar el servidor local
```bash
npm run dev -- --host
```
Acceder a [http://localhost:5173](http://localhost:5173).

## 5. 📌 Convenciones Generales del Código
1. **Soft Delete**: Nunca eliminar filas físicamente (`DELETE`). Usar `activo = false` o `status = 'inactivo'`.
2. **Textos descriptivos en mayúsculas**: Los campos como `descripcion`, nombres o títulos se almacenan y muestran en `.toUpperCase()`.
3. **Validaciones defensivas**: Si una columna o tabla nueva de Supabase aún no está presente en la base de datos remota, el backend debe capturar errores `42703` (undefined column) o `42P01` (undefined table) y usar fallbacks para no interrumpir el flujo del usuario.
